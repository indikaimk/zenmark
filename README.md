# Zenmark

Zenmark is a full-featured, drop-in Markdown editor engine for Ruby on Rails applications using Importmap, Stimulus, and Propshaft/Sprockets.

## Features

- **Write / Split / Preview Modes**: Seamless switching between raw Markdown authoring, side-by-side live split view, and full-width preview.
- **Fullscreen Workspace**: Distraction-free fullscreen editing mode with responsive split-pane support.
- **In-Place AJAX Save & Unsaved Indicator**: Save directly from the toolbar (`Cmd/Ctrl + S` or **Save** button) via `X-Zenmark-Save: true` without losing scroll position or leaving the editor.
- **Mermaid.js Live Rendering**: Automatic client-side rendering of `mermaid` fenced code blocks in both Preview and Split modes.
- **Visual Architecture Studio (`diagram-js`)**: Built-in interactive cloud architecture diagram editor (AWS, Azure, GCP, and general system components) powered by `diagram-js` (MIT) that exports clean SVG files via ActiveStorage and embeds round-trip editable JSON metadata inside the SVG (`<metadata id="cloudqubes-diagram-json">`).
- **Image Upload & Paste / Drag-and-Drop**: Upload images directly via ActiveStorage (`POST /zenmark/images`) with optional resize constraints (`width=300`, `50%`, etc.).

## Installation

Add Zenmark to your application's `Gemfile`:

```ruby
gem "zenmark"
```

And run:

```bash
bundle install
```

Mount the engine in `config/routes.rb`:

```ruby
Rails.application.routes.draw do
  mount Zenmark::Engine => "/zenmark"
end
```

Include the Zenmark stylesheet in your layout (e.g., `app/views/layouts/application.html.erb`):

```erb
<%= stylesheet_link_tag "zenmark/application", "data-turbo-track": "reload" %>
```

## Configuration

By default, Zenmark renders Markdown using `Redcarpet` (if available). You can configure a custom Markdown renderer in `config/initializers/zenmark.rb`:

```ruby
Zenmark.configure do |config|
  config.markdown_renderer = ->(text) { ApplicationController.helpers.markdown(text) }
end
```

## Usage

### Form Builder Helper

```erb
<%= form_with model: @post do |f| %>
  <%= f.zenmark_area :body, rows: 18, placeholder: "Write your content in Markdown..." %>
<% end %>
```

### Standalone Tag Helper

```erb
<%= zenmark_editor_tag "post[body]", @post.body, rows: 16 %>
```

## Architecture & `diagram-js` Integration

To work seamlessly in Rails `importmap-rails` applications without requiring a Node.js build step in the host app, Zenmark separates the upstream `diagram-js` library from Zenmark's custom diagram studio code:

1. **`app/javascript/diagram_js_vendor.js`** *(Auto-generated upstream bundle)*
   - Contains the pure upstream [`diagram-js`](https://github.com/bpmn-io/diagram-js) (MIT) and `tiny-svg` ESM bundle.
   - Do **not** edit this file by hand; it is generated by `./bin/update-diagram-js`.
2. **`app/javascript/zenmark_diagram.js`** *(Zenmark custom studio module)*
   - Clean, readable ES module (~1,000 lines) containing `CloudQubesDiagramStudio`, custom cloud architecture SVG renderers (AWS, Azure, GCP, General shapes), orthogonal connection layouter, rules, and context pad.
   - Imports `Diagram` and core modules from `"diagram_js_vendor"`.
3. **`app/javascript/controllers/zenmark_editor_controller.js`** *(Stimulus controller)*
   - Main editor controller; lazy-loads `"zenmark_diagram"` only when the user opens the Visual Architecture Studio modal.

## Upgrading `diagram-js`

When a new version of `diagram-js` is released, use the included `./bin/update-diagram-js` script to rebuild `app/javascript/diagram_js_vendor.js` in an isolated temporary directory (keeping `node_modules` and `package.json` out of the gem repository):

### Upgrade to the latest version

```bash
./bin/update-diagram-js
```

### Upgrade (or pin) to a specific version

```bash
./bin/update-diagram-js 15.4.0
```

### What `./bin/update-diagram-js` does

1. Creates a temporary directory in `/tmp` and installs the requested `diagram-js` version along with `tiny-svg`, `min-dom`, `min-dash`, and `esbuild`.
2. Bundles the required `diagram-js` modules into `app/javascript/diagram_js_vendor.js` as a single ES module (`--format=esm --minify-whitespace --minify-syntax`).
   - *Note*: Identifier minification (`--minify-identifiers`) is intentionally omitted because `diagram-js` uses `didi` dependency injection, which inspects constructor parameter names at runtime.
3. Stamps the installed `diagram-js` version in the header banner of `app/javascript/diagram_js_vendor.js` and cleans up the temporary `/tmp` workspace automatically.

After running the script, verify the version header and commit the updated vendor bundle:

```bash
head -n 1 app/javascript/diagram_js_vendor.js
git diff --stat app/javascript/diagram_js_vendor.js
```
